# v8 통제비교 공정성 후속 실험 계획 (한계 ①시드 ②레시피 ③용량)

작성 2026-09-01. 배경: v8 GRU↔SS2D 비교의 "잘 학습됐는가" 4층위 진단에서 층위 1~3(무결성·포화·
공정성)은 로그로 입증됐고, 남은 층위 4 한계 3건을 실험으로 닫는 계획. 실행은 radapt 완주(~09-04)
후 GPU 큐. **오늘 완료된 준비(CPU)**: 시드 인프라 + 검증 + 런처 + 용량 하한 실측.

## 준비 완료 (2026-09-01, GPU 불필요분)

- **시드 패치**: `v8_eter_pure/main_train_pure_v8.py` 에 env `SEED` 게이팅 추가 —
  가중치 초기화·셔플(generator)·dataset rng(마스크 offset·flip)·워커별 독립 스트림(worker_init_fn).
  **SEED 미설정 시 기존 런과 코드 경로 동일**(역호환). 런 폴더는 `..._v8_s{SEED}` 로 격리(RUN_SUFFIX
  env 로 별도 지정 가능). fp16 atomics 로 비트단위 재현은 아님(문서화용 독립 시드가 목적).
- **CPU 재현성 검증 PASS**: 동일 seed → 동일 샘플(마스크 offset·flip 포함), 다른 seed → 상이.
- **런처**: `v8_eter_pure/runs/run_v8_multiseed.sh` (시드별 페어 우선 루프 → 적응형 중간판정,
  true-resume + MAX_RETRY 200).
- **부수 수리**: 기존 무시드 경로의 "persistent_workers fork 시 16워커 동일 rng 복제" 문제가
  시드 경로에선 worker_init_fn 재시드로 해소됨 (기존 완주 런은 소급하지 않음 — 양 arm 동일 조건
  이었으므로 비교 공정성 무영향).

## E1 — 멀티시드 축약 (한계 ①, 최우선)

- **설계**: SEED∈{0,1,2} × {GRU, SS2D} × **25ep**(cosine-to-25 **완결 미니런** — 50ep 스케줄 절단이
  아님. 각 시드가 "완주된 런"의 분산을 대리측정; 판정은 ep24 val, VAL_EVERY=2 유지).
- **판정**: (i) 부호 안정성 — 3시드 전부 SS2D>GRU 인가, (ii) paired 차이 d₀,d₁,d₂ 의 평균·범위
  보고. 본편 Δ(ssim 0.0014)와 v9 Δ(0.0005)를 이 분산 위에서 해석(후자는 묻힐 수 있음 — 그 결과도
  "v9 동급, 기여는 radapt" 서사와 일치하므로 그대로 보고).
- **비용**: 페어/시드 ≈ 25×(2.41+3.07)h ≈ **5.7일** → 3시드 **~17일**. 적응형: seed0 → seed1 이
  부호 일치하면 seed2 로 확정, 불일치하면 즉시 중단·재설계.

## E2 — GRU LR 미니스윕 (한계 ②, 선택 — 리뷰 대응 탄약)

- GRU, LR∈{1e-4, 4e-4}×10ep×seed0 (기존 2e-4 와 비교). 목적: "레시피가 GRU 를 불리하게 했다"
  반론 차단. 기본 방어는 이미 있음(레시피가 교수님 ETER/GRU 계보 v5/v6 튜닝 출신). ≈ **2일**.

## E3 — 용량 매칭 (한계 ③): ★구조적 불가능 실측 → 논거로 전환

2026-09-01 CPU 실측 (`PureETER_GRU(n_hidden_1=H, n_hidden_2=H, use_dc=False)` 파라미터 수):

| H (=H1=H2) | total | GRU 스택 | 비고 |
|---|---|---|---|
| **1 (최소)** | **62.9M** | **31.9M** | GRU 스택 최소치가 이미 SS2D arm **전체**(31.2M) 초과 |
| 2 | 101.8M | 70.8M | |
| 3 | 147.9M | 116.8M | |
| 5 | 261.1M | 230.1M | |
| 10 (본편) | 668.2M | 637.1M | UNet 등 공통분 ~31.1M |

- **결론: param-matched GRU 는 이 아키텍처에서 정의 불가능.** flatten-reshape 가 H당 ~64M 를
  강제(하한 63M total)하는 반면 SS2D 스택은 ~0.1M — 파라미터 비대는 튜닝 선택이 아니라 **구조의
  하한**이다. 이 표 자체가 §5-(2) "파라미터 효율" 논거의 정량 보강이며, "매칭 실험이 없다"는
  비판에 대한 1차 답변.
- **선택 실험**: 최소 GRU(H=1, 62.9M) 50ep 1런 (≈**4일**, h/ep 은 68 정도로 짧아질 것 — 실측 후 갱신).
  해석 매트릭스: H1 ≈ H10 → "668M 은 과잉용량" 실증 / H1 ≪ H10 → "GRU 는 그 용량이 실제로 필요"
  — 어느 쪽이든 §5 에 정보.
