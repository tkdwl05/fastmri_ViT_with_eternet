# SSIM 구현 비교 — 우리 평가(skimage) vs 교수님 코드 (2026-10-15)

질문(사용자 10-15): "지금 SSIM 평가는 라이브러리로 하는데, 교수님은 직접 구현한 코드로 했다고 알고 있다 — 둘의 차이는?"
방법:
- 다중 에이전트 조사를 세 갈래로 나눠 진행했다(우리 코드, 교수님 코드, 표준 정의).
- 같은 영상 쌍에 대해 CPU 로 수치를 비교했다.
- 조사 내용을 반박 검증하고, 빠진 부분을 점검했다.
- 저장소 파일은 하나도 고치지 않았고, GPU 는 쓰지 않았다.

근거 자료(git 무시): `results/ssim_impl_compare_2026-10-15/` — `ssim_compare.py`·`summary.md`·`per_slice_variants.csv`·`regions.json`·`verify/`·`workflow_journal.jsonl`.

## 1. 결론

1. **질문의 전제가 조금 다르다.** 교수님도 *평가* SSIM 은 라이브러리(skimage)로 계산했다.
   - 교수님 테스트 스크립트에 있는 SSIM 호출 9곳이 모두 skimage `compare_ssim`/`structural_similarity` 다. 예: `scripts_legacy/myTEST_ViT_ETER_regular_251008.py:403-406`, `myTEST_ViT_ETER_regular_240918.py:373-376`.
   - 교수님이 직접 구현한 `models/hybrid_eternet/u_choh_SSIM.py` 는 **학습 손실(1 − SSIM)에만** 쓰였다(`choh_train_model3_251008.py:198,251` 등). 검증·평가에 쓴 곳은 없다.
2. **교수님 구현 코드는 교과서적인 Wang et al.(2004) SSIM 이다.**
   - Gaussian 11×11, σ 1.5, 모분산(population covariance), padding 없는 'valid' 합성곱을 쓴다.
   - 같은 L 을 넣으면 skimage(`gaussian_weights=True, sigma=1.5, use_sample_covariance=False`)와 최대 차 1e-6 이하로 같다.
   - **비표준인 부분은 동적 범위 L 을 예측 영상에서 자동으로 추정한다는 것 하나다.**
     - 예측 최댓값이 128 을 넘으면 L = 255, 아니면 1 이다(`u_choh_SSIM.py:26-37`).
     - `val_range` 인자는 `SSIM` 클래스에서 무시된다(`:118-119`).
   - 그래서 같은 영상 쌍이라도 영상 세기 단위에 따라 값이 **0.58~0.92** 로 크게 달라진다(§3).
3. **실제 차이는 "라이브러리 대 직접 구현"이 아니라 SSIM 을 *어떻게 부르느냐*에서 나온다.** 아래는 우리 평가(OURS)에서 한 요인만 바꾼 효과다(U-Net 단독, 48 슬라이스).

   | 요인 | 효과 |
   |---|---|
   | 뇌 마스크 제거 | **−0.27** (가장 큼) |
   | data_range 정의 변경 | +0.01 ~ +0.03 |
   | 창(window)·공분산 방식 | 0.007 미만 |

4. **우리 최종 평가에서 버그는 찾지 못했다.** 의도한 프로토콜(`docs/eval_metric_redesign.md`)대로 동작하고, IEIE 방법 절(`paper/ieie/draft_ieie_v8.src.md:64`)도 정확하다.
   - 다만 "fastMRI 관례"라는 표기(`paper/tables/ieie_table1_block.md:1`, CLAUDE.md)는 *볼륨 단위 평균*에 대해서만 맞다. data_range·마스크·자르기는 fastMRI 공식 평가와 다르다.
5. **교수님 논문 수치와 우리 수치는 지금은 직접 비교할 수 없다.**
   - 교수님 논문 SSIM 이 어떻게 계산됐는지 알 수 없다. MATLAB 이었는지 skimage 였는지, 마스크가 있었는지, 범위를 어떻게 정했는지 모른다.
   - 교수님 테스트 스크립트는 슬라이스 하나를 대화식으로 골라 출력할 뿐 집계 코드가 없다(`251008:486-493`). 2025 판에서는 평가가 꺼져 있다(`flag_evalu=False`, `:393`).
   - 교수님 확인 질문으로 남긴다(`docs/professor_settings_compare_2026-10-12.md:178` 에 이미 있음).
6. **⚠ 절차 문제 1건 — 결정이 필요하다(§6).**
   - 교수님 원본 `u_choh_SSIM.py` 에 마스크 분기가 추가돼 있다. 커밋 `afa89a0`(2026-06-16)이고, 원본 무수정 규칙(05-20) 뒤의 일이다.
   - mask=None 경로는 원본과 수치상 같다.

## 3. 수치 비교 (같은 영상 쌍, CPU fp32)

설정:
- val 48 슬라이스(48 볼륨, 대조도별 층화 선택)를 썼다. 모델은 U-Net 단독(v8fix best ep48)과 ETER-net(pod 진행 중 런의 ep36 best)이다.
- OURS 값은 pod 평가의 슬라이스별 CSV 를 최대 차 7.8e-5 로 재현했다. 차이는 AMP fp16 과 CPU fp32 의 차이다.
- **선택 슬라이스가 val 분포와 다르고(AXT2 37.5% 대 val 58%) ETER-net 은 학습 중간 체크포인트라, 이 수치는 경향 확인용이다. 인용하지 않는다.**

**(a) 한 요인씩 바꾼 효과 (U-Net 단독 평균 SSIM)**

| 바꾼 요인 (OURS 기준) | U-Net SSIM | 차이 |
|---|---|---|
| OURS (마스크 안 평균, 마스크 안 max−min) | 0.9216 | — |
| **마스크 제거** (전체 영상, 같은 범위) | 0.6539 | **−0.268** |
| data_range = 슬라이스 GT 최댓값 | 0.9314 | +0.010 |
| data_range = max(GT, 예측) (교수님 테스트 방식) | 0.9317 | +0.010 |
| data_range = 볼륨 GT 최댓값 (fastMRI 방식) | 0.9557 | +0.034 |
| Gaussian 11 창 (교수님 코드의 창) | 0.9147 | −0.007 |
| 모분산 | 0.9221 | +0.0005 |
| 0 padding / 가장자리 제외 / float64 / u_choh 식 마스크 | 0.9216~0.9219 | ≤ 0.0003 |

**(b) 각 정의를 통째로 적용 (U-Net 단독 / ETER-net)**

| 정의 | U-Net | ETER-net |
|---|---|---|
| 우리 평가 (OURS) | 0.9216 | 0.9185 |
| 교수님 테스트 호출 (마스크 없음, max(GT, 예측)) | 0.6714 | 0.6279 |
| Wang 정의 = 교수님 코드에 L = 범위를 넣은 경우 | 0.6835 | 0.6400 |
| 교수님 코드, ViT 로더 ×1e6 단위 (자동 L = 1 ≈ 범위) | 0.6938 | — |
| 교수님 코드, 순수 ETER 로더 ×1e5 단위 (L = 1 > 범위 → 부풀려짐) | 0.9212 | 0.8736 |
| 교수님 코드, 우리 ×1e6 단위 (자동 L = 255 → 깎임) | 0.5758 | — |
| 우리 학습 손실 안에서 쓰는 방식 (정규화 단위, L = 1, 마스크) | 0.8898 | 0.8858 |
| fastMRI 공식 (원래 영상 크기로 자른 경우) | 0.9072 | 0.8631 |

- 교수님 코드는 입력 단위만 바꿔도 같은 영상 쌍에서 0.58 ~ 0.92 가 나온다. 따라서 `u_choh_SSIM` 으로 낸 숫자는 그 로더의 세기 단위에 묶여 있다.
- ×1e5 단위에서는 zero-filled(0.9629)가 U-Net(0.9212)보다 높게 나온다.

**(c) ETER-net − U-Net 짝 차이**

| 정의 | 평균 차 ± SE | ETER-net 이 낮은 슬라이스 |
|---|---|---|
| OURS | −0.0031 ± 0.0003 | 48/48 |
| 마스크 없는 모든 정의 (교수님 테스트·교수님 코드·Wang·fastMRI) | −0.034 ~ −0.048 (11~15 배) | 48/48 |
| 창·공분산만 바꾼 경우 | −0.0031 ~ −0.0032 (Spearman ≥ 0.99) | 48/48 |

- **이 48 슬라이스에서는 시험한 26 가지 정의 모두에서 부호가 같다.** 그러나 크기와 슬라이스별 양상은 달라진다. 마스크 없는 정의의 슬라이스별 차이는 OURS 와 음의 상관이다(Spearman −0.22 ~ −0.36).
- 마스크 없는 정의에서 벌어진 차이의 약 84% 는 뇌 밖이지만 영상 시야 안인 배경 영역에서 나온다. 배경 평균값은 ETER-net 47.6, U-Net 39.3, GT 28.5 로 ETER-net 이 가장 밝다. 마스크 평가는 이 영역을 의도적으로 채점하지 않는다.
- 교수님 테스트 호출로 보면 zero-filled 가 ETER-net 보다 높은 슬라이스가 50%, U-Net 보다 높은 슬라이스가 29% 다. 우리 평가에서는 한 번도 없다.
- 회차 간 변동 수준의 작은 차이(예: GRU 대 SS2D 0.0003~0.0015)에 대해서는 이렇게 본다.
  - 창·공분산 선택이 부호를 바꿀 가능성은 매우 낮다. Δ 가 1e-4 이하로만 움직인다.
  - 마스크 유무는 부호를 바꿀 수 있지만 시험하지 않았다.

## 4. 함의

1. **교수님 수치와의 비교 가능성:** 지금은 비교할 수 없다.
   - 교수님 쪽에서 평가 SSIM 을 계산하는 코드 경로는 테스트 스크립트 하나뿐이고, 마스크 없이 전체 영상을 쓰며 data_range 는 max(GT, 예측)이다.
   - 데이터도 다르다(AXT2 만, 0 채움 테두리 없음).
   - 우리 데이터에서는 마스크 SSIM 이 전체 영상 SSIM 보다 약 0.25 높다(0.92 대 0.67). 원래 영상 크기로 자른 전체 영상 SSIM(0.86)보다는 약 0.06 높다.
2. **모델 비교의 부호:** 이 표본에서는 ETER-net < U-Net 단독이 모든 정의에서 유지됐다. 다만 마스크를 빼면 차이가 배경 밝기 때문에 10배 이상 커지므로, 마스크 유무를 반드시 명시해야 한다.
3. **우리 파이프라인**
   - 최종 평가·학습 중 검증은 의도한 프로토콜이고 버그가 없다. 작은 불일치 2건이 있지만 ep5 에서는 영향이 없었다.
     - 빈 마스크 슬라이스를 평가는 0.0 으로, 검증은 제외로 처리한다.
     - 검증은 4 슬라이스 배치 평균을 다시 평균한다.
   - 학습 손실에는 교수님 코드에서 물려받은 특성이 있다(평가 버그는 아니다).
     - L 이 예측에서 추정되므로 v8fix 단위에서는 L = 1 이다. 그런데 정규화된 GT 범위는 약 1.2~2.6 이라 손실 안의 SSIM(0.89)이 평가 SSIM(0.92)보다 낮다.
     - 예측 최댓값이 128 을 넘으면(발산) L 이 255 로 뛴다.
     - 창이 평가(균일 7)와 다르다(Gaussian 11).
     - 옛 ×1e6 v8 트레이너는 L = 255 로 학습했다(학습 초반에는 2; `docs/v8_training_collapse_audit_2026-10-07.md:43,66`).

## 5. 정정이 필요한 문서 표현 (제안 — 아직 고치지 않음)

- CLAUDE.md 와 `paper/tables/ieie_table1_block.md:1` 의 "fastMRI 관례대로 볼륨 단위":
  - "볼륨 단위 평균(fastMRI 관례)"으로 범위를 좁혀야 한다.
  - 여기에 "SSIM 은 뇌 마스크 안 평균, data_range = 마스크 안 GT max−min (fastMRI 공식 평가와 다름)"을 덧붙인다.
  - 표 머리말은 `make_tables.py` 가 생성하므로, 고치려면 생성 코드 쪽을 고쳐야 할 수 있다.
- `docs/version_evolution.md:157-158` 의 "custom SSIM 버그" 원인 서술은 앞뒤가 맞지 않는다(`presentation_overview.md:312-322`, `summary_2026-06-02.md:81` 도 같다).
  - 문서는 "값 < 1 → L = 1 → SSIM 너무 낮음"이라고 적었다. 그런데 L = 1 이 값 범위보다 크면 SSIM 은 오히려 *부풀려진다*.
  - ×1e6 단위에서 L = 255 가 되어 깎였다는 쪽이 맞는 설명이다.
  - v1~v6 역사 기록이라 근거로는 쓰지 않는다.

  - v8fix 트레이너·스모크·pod 런은 마스크 분기를 쓴다.
  - `sanity_pure_v8.py:93-104` 의 원본 무수정 검사는 `git status --porcelain` 만 보기 때문에, 커밋된 수정은 잡지 못한다.
- **제안 (지금은 아무것도 하지 않음):**
  - pod ETER-net(10-16 종료 예정)과 로컬 A2 가 이 파일을 쓰는 중이므로, 실행 중에는 손대지 않는다(실행 중 런 코드 편집 금지).
  - 두 런이 끝난 뒤에 할 수 있는 정리:
    1. 마스크판을 새 파일(예: `models/hybrid_eternet/u_ssim_masked.py`)로 옮긴다.
    2. v8fix 계열 import 를 바꾼다.
    3. `u_choh_SSIM.py` 는 원본 7d4e4e0 으로 되돌린다.
    4. `sanity_pure_v8.py` 에 `git diff 7d4e4e0 -- <원본 파일>` 검사를 더한다.
    5. `cleanup_log.md` 에 기록한다.
  - 다만 smoke 하네스의 md5 고정값과 pod 실행 판의 재현성에 영향이 있다. 그래서 되돌릴지, 지금처럼 두고 문서에 명시만 할지는 사용자 결정 사항이다.
