## 1. 프로젝트 정의

| 항목 | 값 |
|---|---|
| 데이터 | fastMRI brain multicoil (16코일, real/imag 32채널 입력) |
| 컨트라스트 | "AXFLAIR" 표기되나 실제 혼합(AXT1/POST/PRE/AXT2/FLAIR) — CLAUDE.md 표기 부정확 |
| 가속 | R=4 equispaced, center fraction 0.08 |
| 입력/출력 | 언더샘플 k-space + aliased 이미지 → 단일채널 magnitude |
| 구조 | ViT 인코더 + 시퀀스 디코더(**GRU=ETER** / **Mamba=SS2D**) |
| 베이스라인 | fastMRI pretrained U-Net (chans=256, 496.4M). **checkpoint 2026-06-02 복원·검증 완료**(`models/pretrained/`, §6-①). 0.8858 은 v6 시절 raw SSIM 기록 |
| 환경 | conda `mri_env`, PyTorch + mamba_ssm 2.2.2 |

### 공통 파이프라인
```
입력: aliased image (B,32,H,W) + k-space (B,32,H,W)
   ViT 인코더(공통) ──┐                  ┌── 시퀀스 모델
                      ViT 디코더(공통)    ETER: Bi-GRU(수평→수직)
                      final_linear        SS2D: 4-방향 SSM(+1-iter soft DC block)
                          └──── concat ────┘
                                  │  최종 합성 Conv/RefinementBlock
                              출력 (B,1,H,W)
```
- Loss: `L1 + λ·(1−SSIM)` (λ: v1=0.2 → v2~=1.0). Loss는 fp32(autocast 밖) — label≈959, SSIM 제곱이 fp16 max 초과 방지.
- Optimizer: Adam lr=2e-4, weight_decay 1e-7→(v4)1e-5→(v5~)3e-5.
- Scheduler: (v3~) CosineAnnealingLR 단조 감소(WarmRestarts 톱니 폐기).

### 3.2 두 차례 핵심 발견
1. **발견 ① custom SSIM 버그 (05-04)** — `u_choh_SSIM.py` 의 `val_range=None`→`L=1` 분기. fastMRI raw 값<1이라 SSIM이 인위적으로 낮게 측정됨. skimage 표준으로 재평가 시 v5가 0.7227→**0.8584**로 도약, **SS2D > ETER 로 ranking 반전**, U-Net 갭 0.15→0.027.
2. **발견 ② visual-metric gap (05-20)** — SSIM 0.89인데 시각적으로 흐릿. 원인 4: (1) raw amplitude SSIM의 배경 부풀림(배경 50%+), (2) 비교 슬라이스 below-average 편향, (3) **L1+SSIM의 mean-prediction blurring(본질적)**, (4) 에러맵 colormap 조기 saturation.

### 3.3 Sharpness 회복 실험
- **Tier 1 (TTA/앙상블, 무학습)**: 4-way flip TTA·cross-arch 앙상블 모두 임계(+0.003 SSIM/+0.15dB) 미달 → **전부 negative** (v6가 이미 flip aug 학습됨).
- **Tier 2 (fine-tune)**: gradient L1(v6_1/v6_2)은 항상 PSNR 회귀(over-sharpening) → **edge L1 loss 부적합 확정**. regularization 완화(v6_3)만 작지만 정직한 개선(첫 non-degradation).
- 남은 카드: **v6_4 (VGG perceptual loss)** — config/helper 준비, 미착수.

## 4.6 v8_eter_pure 트랙 — "DC 목발" 가설 검증 (2026-06-19 ~ 2026-07-07, 신규 §)

### 4.6.1 동기 — v7_titan dead-heat 의 confound 제거
§4.5 의 near-tie 에는 풀리지 않는 confound 가 있었다: **ETER v7_titan = GRU + no-DC**,
**SS2D v7_titan = Mamba(SS2D) + 1-iter soft DC block** — 즉 "Mamba 가 GRU 보다 나은가" 를 순수하게
답하지 못했다(DC 유무가 얽혀 있음). 게다가 교수님 원본 ETER-net(논문+코드) 에는 애초에 DC 가 없다
(`docs/eternet_paper_data_consistency.md`, 2026-05-31 확인). v8_eter_pure 는 **ViT 인코더 자체를
빼고** 교수님 순수 ETER-Net(`ETER_hybrid_GRU_DFU`) 위에서 **시퀀스 모델(GRU vs SS2D)만** 바꿔 이
질문을 격리한다. 2×2 설계 {GRU,SS2D}×{no-DC,DC} 중 **no-DC 쌍**(교수님 원본 충실)이 핵심.

| **SS2D no-DC** | 48 | **0.9200** | **0.9140** | **35.16** | **0.0039** | **8.931** | **31M** |
| GRU no-DC | 50 | 0.9182 | 0.9126 | 35.03 | 0.0040 | 9.054 | 668M |

SS2D 가 **5개 지표 전부** 우위, params 는 오히려 **21× 적다**(31M vs 668M). matched-epoch 25개
지점(ep2~50) **전 구간 SS2D≥GRU**(wire-to-wire) — §4.5 의 v7_titan 처럼 중간에 ETER 가 재추월하는
교차점이 **없다**. 전체 val **7334 슬라이스** 기준 per-slice paired 재평가(`v8_eter_pure/eval_paired_v8_nodc.py`)
로도 SS2D 가 5개 지표 전부 **74~78% 슬라이스에서 승리**(Wilcoxon signed-rank p≈0) — aggregate 우위가
소수 슬라이스에 좌우된 게 아님을 확인. 4-way 시각화(`visualize_v8_pure_compare.py`)에서는 GRU 가
두개골 바깥 배경에 반복적 ringing 아티팩트를 보이는 반면 SS2D 는 깨끗함(brain-mask 밖이라 정량
지표엔 미반영, 정성적 근거).

### 4.6.3 해석
1. **"DC 목발" 가설 반박** — v7_titan 의 near-tie(§4.5)가 "SS2D 가 DC 덕을 봤다" 때문이라는 가설은
   틀렸다. DC 를 완전히 뺀 순수 세팅에서 SS2D 는 GRU 를 **오히려 더 확실히** 이긴다.
2. **파라미터 효율** — SS2D 31M 이 GRU 668M 을 이긴다. 순수 ETER-Net 의 GRU 는 668M 으로 과대한데도
   성능은 뒤진다.
3. **§4.5 서사와의 관계** — v7_titan(ViT 트랙) dead-heat 는 두 축(Mamba vs GRU, DC 유무)이 상쇄된
   결과였을 가능성이 높다. ViT 를 걷어내고 sequence-model 축을 격리하니 SS2D 우위가 뚜렷이 드러남.

상세·재현 명령·per-slice CSV 경로는 `docs/v8_eter_pure_rnn_vs_ss2d.md` 참고. DC 축(GRU-DC, SS2D-DC
2런)은 **폐기**(2026-07-15) — 문헌상 비표준·SS2D+DC 가 GRU+DC 와 수치 등가(같은 문서 §7).

## 6. 문제점 / 미해결 이슈

> 식별된 문제·리스크·정합성 결함. 해결된 항목은 [해결됨] 표기.

**① U-Net baseline checkpoint — [해결됨 2026-06-02]**
v6 시절 0.8858 비교에 쓰던 `brain_leaderboard_state_dict.pt` 가 cleanup 으로 소실되어 시스템 전체 부재였음. **2026-06-02 fastMRI 공식**(`dl.fbaipublicfiles.com/fastMRI/trained_models/unet/`)에서 **재다운로드·검증 완료** → `models/pretrained/` (1.85GB, **496.4M params, chans=256, raw state_dict**, 프로젝트 `Unet` 로더와 정확히 일치). 남은 caveat: U-Net 은 320-native 라 v7_titan(384) 평가 시 domain-shift(§6-⑨).

**② SS2D v6 PSNR 불일치 — [규명: best-val vs full-eval]**
`presentation §6.1`=35.96/NMSE0.0081 은 **best-val**(최고 epoch 시점) 값, `visual_metric_gap_v6`·`v6_2` 의 full-eval(7270)=**34.81±2.78/0.00906** 이 정식(SSIM·L1 일치). → §3.4 를 full-eval 기준으로 정정. **함의**: v6_3 의 36.05 도 best-val 로 추정 → "U-Net 대비 +1.39 dB 추월"은 best-val↔full-eval 혼합. **SSIM 추월(0.8924 vs 0.8858)은 견고하나 PSNR 추월 마진은 작을 것**. 단 **v6/v6_3 ckpt 가 이 머신에 없어**(옛 8GB 머신) 정확 마진은 ckpt 회수 후에만 재계산 가능.

**③ INDEX.md 깨진 링크 — [해결됨 2026-07-08]**
`INDEX.md` 가 `SS2D_v1_analysis.md`·`eter_8gb축소.md`·`scheduler_change.md` 를 링크했으나 셋 다 **2026-05-20 cleanup 에서 삭제됨**(내용은 ss2d_v4/v5_changes.md·presentation_overview에 흡수)라 dead link 였음. 2026-07-08 전체 문서 점검에서 3개 행 제거 + 누락돼 있던 문서 9개(cleanup_log.md 등) 및 orphan 문서(`eternet_paper_data_consistency.md`, `v7/README_v7.md`) 추가로 `INDEX.md` 를 CLAUDE.md 와 재동기화.

**④ v6 ↔ v7_titan 척도 차이 — [결함 아님, 단계 경계]**
v6=raw SSIM, v7_titan=masked SSIM 인 것은 버그가 아니라 **프로젝트 두 단계의 경계**다: **v6 이전 = "복원" 단계**(8GB·320·ViT-Small, 원본 ETER-Net 재현 목표) / **v7_titan 이후 = "향상" 단계**(TITAN·384·ViT-Base, 성능 향상 목표). 환경·목적·평가척도가 의도적으로 달라 **0.8913 ↔ 0.9084 를 같은 축에 두는 것이 무의미**. 비교는 **트랙 내부**에서만(SS2D vs ETER, U-Net vs ours), 트랙 간은 "다른 자" 명시.

**⑤ v6_3 결과 미문서화 + ckpt 부재**
presentation(05-28)은 ETER v6_3 "진행 중"으로 기록, 이후 완료·지표 문서 없음. 게다가 **v6_3 ckpt·logs 가 이 머신에 없음**(스크립트/config만 존재, 결과는 옛 머신) → 여기서 확인·재평가 불가. v6_3 채택 확정은 옛 머신 산출물 회수 후.

**⑥ v7_titan EarlyStopping 사실상 비활성 — [50ep 거의 완주, 발산 없음]**
patience=50인데 VAL_EVERY=2 → 50ep 동안 val-check가 **25회뿐** → patience(50)에 도달 불가 → **조기종료가 구조적으로 안 일어남**. ETER와 동일 조건으로 50ep 완주시키려는 **의도된 설계**. SS2D 는 **ep42 까지 단조 상승**(0.9039→0.9121), 과적합·발산 없이 ep43/50 진행 중이라 자동중단 장치 부재가 실제 문제로 발현되지 않음. "epoch10 수동 중간점검"은 통과 완료.

**⑦ GPU1 유휴 (현재 ~11일째)**
v7_titan은 단일GPU 설계(DDP는 effective-batch confounder + 과거 불안정으로 폐기). SS2D 학습 동안 TITAN 1장이 0%. 평가/시각화(ETER 분석 등)를 GPU1에서 병행할 여지 있음.

**⑧ brain mask 이상치 ~17.4% 미해소**
Otsu×0.4 mask 가 ratio<10%(strict해 dim gray matter 누락) 또는 >55%(low-contrast slice에서 threshold가 noise floor 이하) sample 을 ~17.4% 남김. "학습 noise로 흡수" 가정이나 전체 73k 분포 재확인 미완료.

**⑨ U-Net 을 384에서 평가할 때 정합성**
U-Net 은 320-native + fastmri `UnetDataTransform`(z-score) 별도 파이프라인. v7_titan(384, H5 dataloader)과 공정 비교하려면 입력 재구성 + 해상도 domain-shift 감수 → 어느 쪽이든 U-Net 에 불리한 caveat.

**⑩ 외부 의존성 취약**
SS2D 추론은 `mamba_ssm` CUDA 커널 필수(현 2.2.2). 환경 변경 시 SS2D 로드 불가. wandb 로컬 run 대부분 cleanup으로 삭제(클라우드 sync 의존) → 계정 손실 시 gradient histogram 등 raw 복구 불가.

**⑪ AXFLAIR 표기 부정확**
실제 혼합 contrast인데 단일 표기 → contrast별 성능 편차가 평균에 묻힘(per-contrast 분석 미수행).

**⑫ presentation_overview 범위 한계 — [부분 해결 2026-07-08]**
"발표용 통합본"이 v6_3(05-28)에서 멈춰 v7_titan 트랙 전체가 미수록돼 있었음. 2026-07-08 에
`presentation_overview.md` §9 로 v7_titan+v8_eter_pure 요약을 추가(본문 §1~§8 은 v6_3 스코프 그대로
유지, §9 가 이어받는 구조). 단 이 문서(summary_2026-06-11.md) 자체도 v8 이전 시점에 멈춰 있었다는
동일 유형 문제가 있었고, 이번에 §4.6 추가로 해결 — **문서가 최신 상태를 못 따라가는 이 패턴이
